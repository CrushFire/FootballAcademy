# Типографика — единые размеры шрифтов

Чтобы все экраны выглядели одинаково. **Не выдумывать новые размеры** — брать из этой таблицы.

---

## Размеры Tailwind (для справки)

| Класс | Пиксели | Где применять |
|---|---|---|
| `text-3xl` | 30px | очень крупные числа на дашборде (например счёт матча) |
| `text-2xl` | 24px | крупные числа в плашках («Всего заданий: 47») |
| `text-xl`  | 20px | **заголовок страницы** (h1) |
| `text-lg`  | 18px | средний заголовок секции |
| `text-base`| 16px | **имя/название в карточке списка** |
| `text-sm`  | 14px | подзаголовок страницы, мета в карточке, бейджи |
| `text-xs`  | 12px | очень мелкие лейблы, мета внутри плашки |
| `text-[10px]` | 10px | разделители-лейблы внутри карточки (ГТО:, Локальные:) |

## Заголовки страниц

### Крупный (страницы спортсмена, отдельные экраны)

```html
<h1 class="text-xl font-bold text-neutral-900">Индивидуальные задания</h1>
<p class="text-sm text-neutral-500 mt-0.5">Рекомендации и упражнения от тренеров</p>
```

Где используется:
- `Sportsman/WorkoutsPage.vue` — «Индивидуальные задания» / «Рекомендации и упражнения от тренеров»
- `Sportsman/AttendancePage.vue` — «История посещений» / «Все тренировки и статус посещения»
- `Sportsman/TrainingsPage.vue` — «Тренировки» / «Графики тренировок и список занятий»
- `MatchesPage.vue` (общая) — «Матчи» / «Результаты игр»
- `SchedulePage.vue` — «Расписание»
- `NormativesPage.vue` — «Нормативы» / `{{ periodLabel }}`
- `MessagesPage.vue` — «Чаты» (без подзаголовка)

### Мелкий (AdminListLayout — Спортсмены, Группы, Тренировки и т.п. у тренера/админа/медика)

```html
<div class="text-base font-bold text-neutral-900">{{ title }}</div>
```

Где используется:
- Все списки через `AdminListLayout` (19 страниц)

### Внутренний заголовок секции (внутри карточки, светлее основного)

```html
<div class="text-base font-bold text-neutral-400">График тренировок</div>
<div class="text-xs text-neutral-500 mt-0.5">Выбери категорию и параметры для анализа динамики роста</div>
```

## Карточки списка

### Стандартная карточка (внутри AdminListLayout)

```html
<div class="flex items-center gap-3">
  <!-- Аватарка/иконка -->
  <div class="w-10 h-10 rounded-xl bg-neutral-100 flex items-center justify-center flex-shrink-0 text-base font-bold text-neutral-500">
    {{ initials(name) }}
  </div>

  <!-- Имя + подпись -->
  <div class="flex-1 min-w-0">
    <div class="text-base font-semibold text-neutral-800">{{ name }}</div>
    <div class="text-sm text-neutral-400 mt-0.5">
      {{ details }}
    </div>
  </div>
</div>
```

- **Имя/название**: `text-base font-semibold text-neutral-800`
- **Подпись (мета)**: `text-sm text-neutral-400 mt-0.5`
- **Аватарка/иконка-обёртка**: `w-10 h-10`, инициалы внутри `text-base font-bold`
- **Описание** (если есть отдельной строкой): `text-sm text-neutral-600 mt-1.5 line-clamp-2`

### Мини-бейджи в карточке (метки рядом с именем)

```html
<span class="text-xs px-2 py-0.5 rounded-full bg-blue-100 text-blue-600 font-medium">{{ label }}</span>
```

- Размер бейджа: `text-xs px-2 py-0.5 rounded-full`
- Цвета: `bg-{color}-100 text-{color}-600/700` (blue/green/teal/yellow/red)

### Лейблы-разделы внутри карточки (ГТО:, Локальные: и т.п.)

```html
<div class="text-[10px] font-bold text-neutral-600 uppercase tracking-wide mb-0.5">ГТО:</div>
```

## Плашки-сводка (счётчики на дашборде)

```html
<div class="rounded-2xl border border-neutral-200 p-4">
  <div class="text-xs font-bold text-neutral-500 uppercase tracking-wide">Всего заданий</div>
  <div class="text-2xl font-extrabold text-neutral-900 mt-1">{{ count }}</div>
</div>
```

- **Заголовок плашки**: `text-xs font-bold uppercase tracking-wide` (`text-neutral-500` для нейтральной, `text-{color}-700` для цветной)
- **Число**: `text-2xl font-extrabold text-neutral-900`

## Футбольное поле (расстановка игроков)

### Сводная таблица

| Где                                         | Поле                  | Раскладка                                | Кнопка тактики |
|---------------------------------------------|-----------------------|------------------------------------------|----------------|
| **Live-матч (десктоп)** `MatchLivePage`     | целое горизонтальное  | левая половина (тактика)                 | ✅ есть        |
| **Live-матч (мобила)** `MatchLivePage`      | вертикальное 3:4      | верхняя половина (тактика)               | ✅ есть        |
| **Завершённый матч** `MatchDetailPage`      | целое горизонтальное  | универсальная (просто по позициям из БД) | ❌             |

### Live-матч (`Trainer/MatchLivePage`)

- **Десктоп (≥768px)** — `MatchLineupDisplay` → внутри `FootballField`
  (горизонтальная половина поля)
- **Мобила (<768px)** — `FootballFieldMobile` напрямую (вертикальная половина 3:4)
- В обоих случаях поддерживается **выбор тактической схемы**
  (4-4-2/4-4-2 ромб/4-3-3/4-2-3-1/3-5-2/универсальная)
- Выбор сохраняется в `localStorage` отдельно для каждого устройства
  и стороны матча:
  - десктоп: `match-formation:{matchId}:{home|away}`
  - мобила:  `match-formation-mobile:{matchId}`
- Если матч «обе наши команды» — для просмотра away-команды поле
  **зеркалится** (десктоп — по X, мобила — по Y) через prop `mirror`
- Пустые слоты — пунктирные кружки с подписью позиции и подсказкой
  при hover (список подходящих позиций по приоритету)

### Просмотр завершённого матча (`Trainer/MatchDetailPage`)

- Использует **`FootballField` напрямую** с локальным `fieldPositions` computed
- **Всегда универсальная расстановка** (без выбора тактики)
- Без `MatchLineupDisplay`, без `localStorage`, без пустых слотов
- Каждый игрок встаёт по своей позиции из БД; если позиция не найдена —
  fallback на `ST`
- Передавать в `result.push({...})` обязательно поле `position: pos` —
  иначе подпись под игроком (`pos.position || 'ST'`) у всех будет «ST»
- **Известная проблема**: координаты `FIELD_POSITIONS` в этом файле — старые
  (наследие до слотовой модели), некоторые позиции прижаты к низу
  (`ST: y=85`), нападающие смотрятся «придавленными». Стоит синхронизировать
  с `DEFAULT_POSITIONS` из `MatchLineupDisplay` или сделать общую константу.

### Координаты позиций

Стандартные коды позиций из `Position.cs` в БД: `GK, CB, LB, RB, LWB, RWB, CDM, CM, CAM, LW, RW, ST, CF, SS`.

**Искусственные коды `CB2`, `CM2`, `CM3`** существуют только в координатах
компонентов поля (для рендера дублей на одной позиции). В БД их нет —
второй CB приходит как обычный `CB` с другим `sportsmanId`. Дубли обрабатываются
через `Map<position, FieldPlayer>` (берётся первый), либо через слотовую модель
(каждый CB-слот забирает по одному игроку через `playersOnField.splice`).

## Шкала цветов текста

| Класс | Описание | Где |
|---|---|---|
| `text-neutral-900` | основной текст, заголовки | h1, ФИО на профиле |
| `text-neutral-800` | имя в карточке | ФИО в списке |
| `text-neutral-700` | обычный текст | абзацы |
| `text-neutral-600` | вторичный текст | подписи к данным |
| `text-neutral-500` | подзаголовки, подсказки | под h1 |
| `text-neutral-400` | мета-инфо, заглушённые элементы | даты, позиция |
| `text-neutral-300` | сильно заглушённый | плейсхолдеры |

## Что НЕ делать

- Не использовать `text-base` для подзаголовка под `h1` (он крупнее заголовка-мелкого = путаница). Подзаголовок всегда `text-sm`.
- Не миксовать `text-base font-bold` (мелкий заголовок) и `text-xl font-bold` (крупный) в одной секции — выбрать один тип.
- Не использовать произвольные значения типа `text-[15px]` — только из таблицы.
